# اسنپ | نمونه رابط کاربری درخواست سفر

یک پروژه فرانت‌اند فارسی برای تجربه‌ی ساده‌ی درخواست سفر شهری؛ ساخته‌شده با **Ionic و Angular**. در این برنامه مسافر می‌تواند مبدأ و مقصد را روی نقشه انتخاب کند و راننده می‌تواند درخواست‌های موجود را ببیند. احراز هویت، سفر و پرداخت در حالت توسعه به‌صورت آزمایشی شبیه‌سازی می‌شوند.

> این پروژه یک نمونه آموزشی و نمایشی است و به سرویس رسمی اسنپ یا درگاه پرداخت واقعی متصل نیست.

## امکانات

- ورود با شماره موبایل و کد تأیید آزمایشی و ساخت حساب مسافر یا راننده
- انتخاب مبدأ و مقصد روی نقشه و نمایش آدرس تقریبی نقطه انتخاب‌شده
- نمایش مسیر و برآورد قیمت برای اسنپ اکو، پلاس و موتور
- ثبت و لغو درخواست سفر و مشاهده وضعیت سفر و اطلاعات راننده
- پنل راننده برای مشاهده و پذیرش درخواست‌های سفر
- صفحه حساب کاربری و پرداخت نمایشی پس از پایان سفر
- رابط راست‌به‌چپ فارسی با فونت وزیرمتن و پشتیبانی از ظاهر روشن و تاریک سیستم

- npm
- اینترنت برای دریافت وابستگی‌ها، نمایش کاشی‌های نقشه، تبدیل مختصات به آدرس و محاسبه مسیر
- مرورگر جدید؛ برای استفاده از موقعیت فعلی، اجازه دسترسی به موقعیت مکانی لازم است

## نصب و اجرا

در پوشه پروژه، یعنی پوشه‌ای که فایل `package.json` در آن قرار دارد، دستورهای زیر را اجرا کنید:

</div>

```bash
npm install
npm start
```

<div dir="rtl">

سپس آدرس `http://localhost:4200` را در مرورگر باز کنید. حالت توسعه به‌طور پیش‌فرض از داده‌های آزمایشی استفاده می‌کند و برای ورود و درخواست سفر به سرور محلی نیاز ندارد.

## راهنمای استفاده از نسخه نمایشی

۱. یک شماره موبایل معتبر با قالب `09` و ۱۱ رقم وارد کنید.

۲. کد آزمایشی `12345` را وارد کنید و در اولین ورود، اطلاعات حساب و نقش مسافر یا راننده را تکمیل کنید.

۳. در پنل مسافر، مبدأ و مقصد را با حرکت دادن نقشه انتخاب و تأیید کنید. پس از محاسبه مسیر، نوع سفر را انتخاب و درخواست را ثبت کنید.

۴. در پنل راننده، درخواست موجود را بپذیرید. در حالت آزمایشی وضعیت سفر پس از پذیرش به‌مرور تغییر می‌کند؛ بعد از پایان سفر، پرداخت نمایشی در پنل مسافر در دسترس است.

برای آزمایش هم‌زمان دو نقش می‌توانید از دو زبانه در یک مرورگر استفاده کنید: ابتدا حساب مسافر و درخواست سفر را بسازید، سپس در زبانه دیگر با شماره‌ای متفاوت وارد حساب راننده شوید. داده‌های آزمایشی بین زبانه‌های یک مرورگر و یک مبدأ مشترک هستند؛ پنجره ناشناس یا مرورگری دیگر معمولاً فضای ذخیره‌سازی جداگانه دارد. وضعیت سفر فعال در حافظه صفحه مسافر نگهداری می‌شود، پس در طول آزمایش آن صفحه را باز نگه دارید.

> پرداخت صرفاً شبیه‌سازی می‌شود؛ اطلاعات کارت دریافت نمی‌شود و پولی جابه‌جا نمی‌شود.

## پیکربندی و داده‌ها

تنظیمات توسعه در `src/environments/environment.ts` قرار دارد:

</div>

```ts
export const environment = {
  production: false,
  apiUrl: 'http://localhost:3000/api',
  useMock: true,
};
```

<div dir="rtl">

- با فعال بودن `useMock`، درخواست‌های API برنامه توسط شبیه‌ساز داخلی پاسخ داده می‌شوند؛ با این حال نقشه، آدرس و مسیریابی همچنان به سرویس‌های اینترنتی وابسته‌اند.
- حساب‌ها، توکن آزمایشی، سفرهای نمایشی و وضعیت پرداخت در فضای `localStorage` همان مرورگر ذخیره می‌شوند؛ پاک‌کردن داده‌های سایت آن‌ها را حذف می‌کند.
- سرویس‌های نقشه و مسیریابی برای انجام کار خود مختصات انتخاب‌شده را دریافت می‌کنند.
- برای اتصال به API واقعی باید `apiUrl` و `useMock` را متناسب با محیط تغییر دهید و سروری سازگار با قراردادهای پیاده‌سازی‌شده فراهم کنید. جریان فعلی حساب کاربری به توکن آزمایشی و ذخیره‌سازی محلی وابسته است و پیش از استفاده واقعی به تکمیل و بازبینی نیاز دارد.
- تنظیمات انتشار در `src/environments/environment.prod.ts` است. آدرس `https://api.example.com/api` یک نشانی نمونه است و باید پیش از استقرار جایگزین شود؛ در این حالت `useMock` غیرفعال است.

## دستورهای کاربردی

| دستور | کاربرد |
| --- | --- |
| `npm start` | اجرای سرور توسعه |
| `npm run build` | ساخت نسخه انتشار در پوشه `www` |
| `npm run watch` | ساخت توسعه و بازسازی پس از تغییر فایل‌ها |
| `npm run test:unit` | اجرای تست‌های واحد |
| `npm run test:e2e` | اجرای تست‌های سرتاسری با Playwright |
| `npm test` | اجرای تست‌های واحد و سپس سرتاسری |
| `npm run lint` | بررسی ESLint، نوع‌های تست سرتاسری و قالب‌بندی |

برای اجرای Playwright ممکن است لازم باشد مرورگرهای آن را یک‌بار نصب کنید:

</div>

```bash
npx playwright install chromium
```

<div dir="rtl">

> تست سرتاسری فعلی هنوز متن صفحه پیش‌فرض Ionic را بررسی می‌کند و با رابط فعلی هماهنگ نیست؛ بنابراین ممکن است `npm run test:e2e` و در نتیجه `npm test` ناموفق شوند. تست واحد را می‌توان جداگانه اجرا کرد.

## ساختار پروژه

</div>

```text
src/
├── app/
│   ├── core/          سرویس‌ها، مدل‌ها، محافظ مسیرها و API آزمایشی
│   ├── home/          نقشه و مراحل درخواست سفر مسافر
│   ├── driver/        پنل راننده
│   ├── login/         ورود با شماره موبایل و کد تأیید
│   ├── register/      تکمیل اطلاعات حساب
│   ├── account/       اطلاعات حساب کاربری
│   ├── payment/       پرداخت نمایشی
│   └── shared/map/    مؤلفه مشترک نقشه
├── environments/      تنظیمات توسعه و انتشار
├── global.scss        استایل‌های سراسری
└── theme/             متغیرهای ظاهری برنامه
e2e/                   تست‌های Playwright
```

<div dir="rtl">

پیکربندی اولیه Capacitor در `capacitor.config.ts` موجود است. خروجی وب در `www` ساخته می‌شود؛ برای ساخت اپلیکیشن بومی باید پلتفرم موردنظر و پیش‌نیازهای آن جداگانه به پروژه اضافه شوند.
